# model_lorawan

Аналитическая модель и программный комплекс на языке Python для оценки энергопотребления, бюджета энергии и срока автономной работы оконечного узла сети LoRaWAN (классы A и B) с поддержкой калибровки по экспериментальным осциллограммам макета на базе платы **DXL-IoT**.

## Описание проекта

Существующие методы оценки энергопотребления узлов LoRaWAN плохо переносятся между аппаратными платформами из-за различного учёта интервалов ожидания приёмных окон (`RX1`/`RX2`), идеализации источника питания и несопоставимых границ учёта энергии. 

В данном проекте реализован комбинированный подход:
1. **Априорная аналитическая модель** на основе паспортных характеристик компонентов (технических описаний).
2. **Калибровка и верификация модели** по данным натурных измерений на макете оконечного узла (плата DXL-IoT, диапазон EU433, сервер ChirpStack) с раздельным учётом энергии по двум цепям питания (радиомодуль и микроконтроллерная плата с датчиком) при $U = 3{,}3\text{ В}$.

### Аппаратные конфигурации макета (DXL-IoT)
* **Конфигурация К1:** стек LoRaWAN выполняется на микроконтроллере **ESP32** (80 / 160 / 240 МГц).
* **Конфигурация К2:** стек выполняется на **ATmega328P** (2 / 4 / 8 МГц), ESP32 переведён в режим гибернации.
* **Радиомодули:** DRF1278F (Semtech SX1278, интерфейс SPI) и модуль EBYTE (диапазон EU433, $BW = 125\text{ кГц}$, $CR = 4/5$, $P_{\text{tx}} = 10\text{ дБм}$).
* **Датчик:** BME280 (интерфейс I2C, принудительный режим `forced mode`).

## Проверяемые научные гипотезы

* **Г1 (Влияние SF):** Переход от SF7 к SF12 увеличивает время в эфире (ToA) в 24–26 раз, однако полная энергия радиотранзакции возрастает меньше (примерно на порядок), так как окно `RX2` всегда открывается на скорости DR0 (SF12), а затраты на пробуждение и обработку не зависят от SF.
* **Г2 (Вклад режима сна):** При периодах передачи порядка десятков минут и более основной вклад в бюджет энергии вносит ток сна платы (включая стабилизаторы и периферию), поэтому выбор режима сна влияет на срок службы сильнее, чем выбор SF.
* **Г3 (Надбавка класса B):** Работа в классе B увеличивает средний ток на величину, определяемую приёмом маяка каждые 128 с и периодичностью ping-слотов ($k = 0\dots 7$); при малых периодах ping-слотов эта надбавка становится доминирующей.
* **Г4 (Эффективность ADR):** На малых расстояниях механизм ADR переводит узел на SF7–SF9 и снижает энергию передачи по сравнению с фиксированным SF12 без заметного снижения доли доставленных пакетов (PDR).
* **Г5 (Поведение МК в паузах ожидания):** Энергия цикла определяется не столько тактовой частотой МК, сколько его режимом в интервалах ожидания окон `RX1` и `RX2` (активное ожидание против перехода в `light sleep`).
* **Г6 (Точность калибровки):** Априорная модель по техническим описаниям занижает потребление в режимах сна и ожидания из-за неучёта токов стабилизаторов и обвязки платы; после пофазовой калибровки погрешность оценки среднего тока и энергии цикла не превышает **10 %**.

## Варьируемые факторы и базовая точка

| Фактор | Уровни в вычислительном эксперименте | Базовая точка |
| :--- | :--- | :--- |
| Коэффициент расширения спектра ($SF$) | 7, 8, 9, 10, 11, 12 | 9 |
| Механизм ADR | выкл.; вкл. | выкл. |
| Расстояние до шлюза ($d$), км | 0,05 – 15 (15 уровней) | лаб. (3–5 м) |
| Размер полезной нагрузки ($L$), байт | 4, 12, 24, 51 | 12 |
| Частота опроса датчика ($f_{\text{sens}}$), Гц | 1; 0,1; 1/60 | 1/60 |
| Тактовая частота МК ($f_{\text{cpu}}$), МГц | ESP32: 80, 160, 240; ATmega: 2, 4, 8 | 80 (ESP32, К1) |
| Класс устройства | A; B ($k = 7, 4, 1$) | Класс A |
| Интенсивность саморазряда ($\lambda$) | 0; 1 %/год ($\text{Li-SOCl}_2$); 3 %/мес (Li-ion 18650) | 0 |
| Период передачи ($T_{\text{tx}}$), мин | 1 – 1440 | 1 (60 с) |

## Архитектура проекта

В соответствии с п. 2.6.3 методики, программный комплекс разделён на следующие модули:

```text
model_lorawan/
├── config/
│   ├── apriori_params.yaml      # Исходные данные из технических описаний (Таблица 2.3)
│   └── calibrated_params.yaml   # Параметры состояний после калибровки на стенде
├── src/
│   ├── __init__.py
│   ├── states.py                # Единый перечень состояний (WU, TX, WAIT_RX1, RX1, WAIT_RX2, RX2, PP, SLEEP, BEACON, PING)
│   ├── phy.py                   # Время в эфире (ToA), проверка по Таблице 2.4
│   ├── mac.py                   # Временные диаграммы классов A и B, окна приёма (ф. 2.2, 2.5)
│   ├── channel_adr.py           # Логарифмическая модель затухания и алгоритм ADR (ф. 2.6, 2.7)
│   ├── node.py                  # Расчёт токов по цепям, времени безубыточности сна и бюджета энергии (ф. 2.1, 2.3, 2.4, 2.9)
│   ├── battery.py               # Срок автономной работы с учётом саморазряда (ф. 2.8)
│   ├── experiments.py           # Вычислительный эксперимент (~156 тыс. точек), эластичность (ф. 2.11) и ПФЭ 2^3 (ф. 2.12)
│   └── measurements.py          # Обработка осциллограмм, метод трапеций (ф. 2.10), статистика по ГОСТ Р 8.736-2011 (ф. 2.13, 2.14)
├── tests/
│   └── test_phy_toa.py          # Юнит-тесты расчёта времени передачи по Таблице 2.4
├── requirements.txt
└── README.md
